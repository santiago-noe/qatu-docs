Sigue docs/04-arquitectura.md y docs/03-dominio.md. Estructura: 3 repos git independientes por producto (qatu-api, qatu-app, qatu-docs); no monorepo ni submodules.

Stack fijo backend (qatu-api): Go 1.26+, arquitectura hexagonal (internal/core/{domain,port,service}, internal/adapter/{inbound,outbound}), Fiber v3, PostgreSQL 18 vía pgx v5, migraciones SQL planas numeradas en migrations/ (NNNN_nombre.up.sql / .down.sql), Redis 8 (go-redis v9) para sesiones, códigos, rate limiting y jobs, argon2id, zerolog, viper (env vars con prefijo APP__), golang.org/x/oauth2. Rutas versionadas /api/v1. Auth por sesión en cookie httpOnly + session store en Redis (no JWT stateless), 2FA, roles con middleware require_role.

Stack fijo frontend (qatu-app): Next.js 16 App Router, React 19, TypeScript estricto, Tailwind v4, shadcn/ui + radix-ui, lucide-react, recharts, bun. Organización feature-sliced: features/{public,protected,auth}/<feature>/{components,lib}. Rutas en app/(public), app/(protected)/dashboard, app/auth. BFF en app/api (proxy server-side al backend Go; el navegador nunca llama al backend directo). proxy.ts protege rutas por cookies de sesión. gateway.js expone un solo puerto y enruta el WebSocket directo al backend.

Tests: backend con `go test` (unitarios de dominio con tabla de casos + integración contra Postgres/Redis reales con Testcontainers); frontend con bun test (unitarios de lib/ y componentes) y Playwright (e2e y accesibilidad con axe); presupuesto de rendimiento con Lighthouse CI. Infra: Dockerfile + entrypoint.sh y compose.yml (db + redis) por repo; GitHub Actions por repo.

Incluye en el plan: qué carpetas y archivos concretos se crean o modifican en cada repo, modelo de datos con índices y restricciones (si aplica), contratos de API (método, ruta, request, response, errores), eventos de dominio, jobs programados, permisos por rol, parámetros que van a platform_settings, y el plan de pruebas. No agregues dependencias fuera de este stack sin justificarlas en research.md.
